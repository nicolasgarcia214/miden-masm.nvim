1. INTRODUCTION                                      *miden-masm-introduction*

miden-masm.nvim provides Miden Assembly (`.masm`) support:

- tree-sitter highlighting, indentation, folds and textobjects (requires
  nvim-treesitter and the `masm` parser; run `:TSInstall masm`). Once the
  parser is installed these activate automatically per buffer: the ftplugin
  calls `vim.treesitter.start()` and sets 'indentexpr'/'foldexpr', since
  nvim-treesitter's main branch enables nothing by itself. Opt out with
  |g:masm_no_treesitter|.
- go-to-definition, references, project-wide rename, document symbols,
  completion and hover docs, implemented with plain text analysis of the
  project: no language server and no parser required
- static stack analysis: per-instruction operand-stack simulation with
  |vim.diagnostic| errors for call-ABI violations and stale or reordered
  `# => [...]` comments, plus an inferred-stack ghost-text overlay
  (|:MasmStackToggle|)
- optional debugging through |nvim-dap|: the plugin registers the `miden`
  adapter and launch/attach configurations for `miden-debug` and
  `miden-client` (|miden-masm-dap|)

Neovim ships a `masm` filetype for Microsoft Macro Assembler; this plugin
corrects its settings (comments, indentation, matchit words) for Miden in
`after/ftplugin/masm.lua`. On Neovim 0.10, which has no built-in `*.masm`
detection (it was added in 0.11), the plugin registers the filetype mapping
itself.

Run `:checkhealth masm` to verify the installation.

2. INSTALLATION                 *miden-masm-install* *miden-masm-requirements*

Requirements:

- Neovim 0.10.4 or newer.
- nvim-treesitter (https://github.com/nvim-treesitter/nvim-treesitter, main
  branch) and a C compiler -- only for the optional tree-sitter parser
  (highlighting, indentation, folds). Navigation, hover, completion and
  stack analysis are text-based and work without it.
- nvim-dap (https://github.com/mfussenegger/nvim-dap) plus miden-debug
  and/or miden-client builds supporting `--start-debug-adapter` -- only for
  the optional debugger (|miden-masm-dap|).

With lazy.nvim (https://github.com/folke/lazy.nvim): >lua
    {
      "nicolasgarcia214/miden-masm.nvim",
      lazy = false,
    },
    {
      "nvim-treesitter/nvim-treesitter",
      branch = "main",
      build = ":TSUpdate",
    },
<
The plugin registers the `masm` parser with nvim-treesitter at startup; run
`:TSInstall masm` once to compile and install it. The revision is pinned to
the exact grammar the bundled queries were ported against.

On LazyVim (https://www.lazyvim.org/), which wraps nvim-treesitter and adds
an `ensure_installed` option upstream does not have, the parser can be
installed automatically instead: >lua
    {
      "nvim-treesitter/nvim-treesitter",
      opts = function(_, opts)
        table.insert(opts.ensure_installed, "masm")
      end,
    },
<
Verify the setup with `:checkhealth masm`.

3. MAPPINGS                                              *miden-masm-mappings*

All mappings are buffer-local to `masm` buffers.

                                                    *miden-masm-gd* *miden-masm-CTRL-]*
gd / CTRL-]        Jump to the definition of the name under the cursor:
                   procedures (`exec.`/`call.`/`procref.` targets), kernel
                   procedures (`syscall.` targets), constants and types.
                   On a module qualifier, a `use` path segment or a
                   `pub mod` name, jump to the module's file instead.
                   Implemented via 'tagfunc', so the full tag machinery
                   applies: CTRL-T to go back, |:tag|, |:tjump|, etc.

                                                                *miden-masm-K*
K                  Show hover documentation in a floating window. Names
                   resolve exactly like `gd`: the float shows the
                   definition's `#!` doc comment, `@` attribute lines and
                   signature (plus the source file for cross-file
                   definitions); module qualifiers show the module file's
                   leading doc block. A bare opcode shows its description
                   and stack effect from the bundled Miden instruction
                   reference. Press K again to focus the float; `q` or
                   moving the cursor closes it.

                                                              *miden-masm-grr*
grr                Find references to the symbol under the cursor across the
                   project and populate the quickfix list, definition first.
                   Every candidate usage is resolved to its definition, so
                   usages through renamed imports and re-export chains are
                   included. On a module qualifier, list the `use` statements
                   importing that module instead. The scan runs in the
                   background (time-sliced on the event loop; the deadline
                   is checked between files, so a single enormous file is
                   still scanned in one uninterrupted slice) and opens the
                   quickfix list when it completes; starting a new scan
                   cancels the one in flight.

                                                              *miden-masm-grn*
grn                Rename the symbol under the cursor across the project
                   (prompts for the new name). See |:MasmRename|.

                                                               *miden-masm-gO*
gO                 List the buffer's definitions (procs, consts, types,
                   submodules, `begin` entrypoint) in the location list.

4. COMMANDS                                              *miden-masm-commands*

                                                            *:MasmRebuildIndex*
:MasmRebuildIndex  Drop the cached project index and resolution caches. The
                   index rebuilds on the next use (a jump, completion, or
                   stack-analysis pass). Rarely needed: plain
                   edits are picked up via file mtimes, and saving a new
                   `.masm` file or a `miden-project.toml` from Neovim
                   refreshes the index automatically. Use it after deleting
                   or moving files, after changes made outside Neovim (e.g.
                   `git pull`), or after changing |g:masm_goto|.

                                                                 *:MasmRename*
:MasmRename [name] Rename the symbol under the cursor across the project
                   (prompting when [name] is omitted). Renames the
                   definition, every reference that spells the
                   definition-site name, and the original side of importing
                   or re-exporting `use { orig as alias }` items; sites that
                   use an `as` alias keep their alias, which still resolves.
                   Edits are applied to buffers and left unsaved for review
                   -- inspect with |:ls|, write with |:wa|, or undo per
                   buffer. Renaming onto a name already defined in the
                   definition's file is refused (it would silently merge the
                   two symbols), as are invalid identifiers. The prompt
                   captures the symbol under the cursor at prompt time, so
                   an asynchronous |vim.ui.input| implementation cannot
                   rename whatever the cursor later moved to. Bare
                   instruction tokens are never rename targets: a procedure
                   named after an opcode (Miden's std::math::u64 defines
                   `add`, `and`, `eq`) does not drag the opcodes themselves
                   into the rename. Modules cannot be renamed (their name is
                   a file name).

                                                            *:MasmStackToggle*
:MasmStackToggle   Toggle the inferred-stack ghost-text overlay for the
                   current buffer. See |miden-masm-stack|.

                                                               *:MasmDapState*
:MasmDapState      Show the Miden VM state (cycle, operand stack, call
                   stack) most recently pushed by the debug adapter, in a
                   floating window. Only defined when |nvim-dap| is
                   installed. See |miden-masm-dap|.

5. COMPLETION                                          *miden-masm-completion*

The ftplugin sets 'omnifunc' (CTRL-X CTRL-O in insert mode). Candidates come
from the same index and imports navigation uses, so the list is exactly the
set of names `gd` could resolve:

- after `exec.` / `call.` / `procref.`: local procedures, imported symbols
  and module qualifiers; after `exec.mod::`, that module's procedures
  (re-exports included, renames applied)
- after `syscall.`: the kernel library's procedures
- after `push.`: constants -- local, imported and `mod::`-qualified
- at an instruction position: opcodes from the bundled Miden instruction
  reference, each showing its stack effect in the popup menu and its
  description in the preview/info float, plus control-flow keywords

Procedure candidates show the callee's `[inputs] -> [outputs]` doc contract
in the menu -- the de facto type signature in Miden code.

6. STACK ANALYSIS                                           *miden-masm-stack*

The analyzer simulates the operand stack instruction by instruction inside
every procedure that declares how it is invoked (`#! Invocation:` doc tag,
or a `@note_script`-style attribute with a padded 16-element `Inputs:`
contract), and inside every `begin..end` entrypoint block -- entrypoints
always run on the 16-element physical stack (declared `#! Inputs:` enter
named and zero-padded to 16; without a contract they enter unknown), and
since the VM caps program stack outputs at 16, a program ending deeper
than 16 is flagged as an error. Cross-procedure effects come from the
callee's declared `#! Inputs:`/`#! Outputs:` stack contract -- callee
bodies are never analyzed on behalf of a caller.

Diagnostics are published through |vim.diagnostic| (source `masm-stack`) and
render however your diagnostic config says; the plugin never draws them
itself. Codes:

  exit-depth        ERROR  A `call`/`syscall`/`dyncall`-invoked procedure
                           returns at a stack depth other than 16. The VM
                           rejects every invocation of such a procedure at
                           runtime (`InvalidStackDepthOnReturn`).
  abi-16            ERROR  An `Invocation: call`/`syscall`/`dyncall`
                           procedure declares `Inputs:`/`Outputs:` that do
                           not sum to the mandatory 16 elements.
  comment-stale     WARN   A handwritten `# => [...]` comment disagrees with
                           the simulated stack width at that point.
  comment-reordered WARN   A handwritten comment lists exactly the same
                           named elements as the simulation but in a
                           different order -- a swapped-operands comment.
                           Only raised when every element is named on both
                           sides and the name multisets match, so renamed
                           or anonymous elements can never trip it.
  exec-net          WARN   An `exec`-invoked procedure's body leaves a
                           different number of elements than its `Outputs:`
                           declares.
  caller-underflow  WARN   An `exec`-invoked procedure consumes elements
                           beneath its declared `Inputs:` -- it eats the
                           caller's stack.
  branch-depth      WARN   `if.true` arms leave different depths without a
                           diverging (`push.0 assert`) or re-normalizing
                           (`call`/`dyncall`) arm to explain it.
  while-net         WARN   A `while.true` body does not leave exactly one new
                           element (the continuation flag).
  callee-unresolved HINT   A callee's stack effect could not be determined;
                           analysis resumes at the next `# => [...]` comment.
                           Hidden unless `bail_hints` is set.

One diagnostic comes from the resolver rather than the simulator (source
`masm-goto`):

  unrecognized-import WARN A `use` statement matches none of the forms the
                           resolver understands. Resolution is text-based
                           against the current dialect's import forms; a
                           future form would otherwise fail silently
                           (imports not seen, navigation and callee
                           contracts quietly degraded). This canary makes
                           dialect drift loud instead.

The overlay (off by default, |:MasmStackToggle|) appends ghost text like
`# => [VALUE, pad(16)]` at end of line, in the same notation Miden code uses
for handwritten comments. In "auto" mode only lines without a handwritten
tracker get ghost text -- plus lines whose tracker is stale, which show the
corrected state highlighted with `MasmStackVirtualTextStale`. Highlight
groups: `MasmStackVirtualText` (links to `NonText`) and
`MasmStackVirtualTextStale` (links to `DiagnosticVirtualTextWarn`).

Analysis runs on |InsertLeave| and normal-mode edits (debounced) and on
every write, whole-buffer, synchronously and bounded: oversized buffers,
per-procedure instruction budgets and cross-file lookup budgets all degrade
to skipped procedures with a stated reason, never to guesses. The same
refuse-don't-guess rule covers unknown mnemonics, positional indices the
assembler rejects (`movup.99`), and body tokens sharing the declaration
line (`proc f push.1 drop end` -- legal MASM, but events are line-based):
each bails the procedure with a reason instead of simulating wrongly.

7. DEBUGGER                                                   *miden-masm-dap*

When nvim-dap (https://github.com/mfussenegger/nvim-dap) is installed, the
plugin registers a `miden` debug adapter and three default configurations
for `masm` buffers (your own `dap.configurations.masm`, if set, is left
untouched):

- "Debug current file (miden-debug)": launches
  `miden-debug --start-debug-adapter` on the current `.masm`/`.masp` file
- "Debug transaction script (miden-client)": launches
  `miden-client exec --script-path <file> --start-debug-adapter`
- "Attach to Miden DAP server": connects to 127.0.0.1:4711

Launching picks a free local port (falling back from the configured one)
and waits for the backend's "DAP server listening" line before connecting;
a probe connection would consume the single DAP connection the server
accepts. Backend output is shown on failure. The backends must support
`--start-debug-adapter` (recent miden-debug / miden-client builds).

Launch configuration keys (nvim-dap substitutes `${file}` and
`${workspaceFolder}`): `program`, `midenDebugPath`, `inputs`, `entrypoint`,
`sysroot`, `searchPath`, `linkLibraries`, `sourcePathPrefixes`,
`programArgs` (miden-debug); `scriptPath`, `midenClientPath`, `accountId`
(miden-client); `runtime` ("debugger"/"client", inferred from
`program`/`scriptPath` when omitted); `host`, `port`, `cwd` (both).

Before each stop the adapter pushes a `miden/uiState` event with the VM
cycle, operand stack and call stack; |:MasmDapState| shows the latest one.

Concurrent sessions are supported: each launch owns its backend process
(keyed by its DAP port), a session's end kills only its own backend, and
the backend's output pipes stay drained for the process's whole lifetime.
Disable the whole integration with |g:masm_no_dap|.

                                                                 *g:masm_goto*
g:masm_goto        Optional table: >lua
                     vim.g.masm_goto = {
                       extra_roots = { "~/work/miden-vm" },
                       ignore_dirs = { "target", "node_modules" },
                     }
<
                   extra_roots: additional directories scanned for
                   `miden-project.toml` libraries. Point at a miden-vm
                   checkout to resolve `std::..` and `miden::core::..`.

                   ignore_dirs: directory names never descended into while
                   indexing (replaces the default list). Hidden directories
                   are always skipped.

                                                   *g:masm_no_default_mappings*
g:masm_no_default_mappings
                   When true, the plugin defines no keymaps; call
                   `require("masm.goto").references()`, `.rename()`,
                   `.document_symbols()` and
                   `require("masm.hover").hover()` from your own mappings
                   (see |miden-masm-api|). 'tagfunc' and 'omnifunc' are
                   still set, so CTRL-], |:tag| and CTRL-X CTRL-O keep
                   working.

                                                        *g:masm_no_treesitter*
g:masm_no_treesitter
                   When true, the ftplugin does not call
                   `vim.treesitter.start()` and leaves 'indentexpr',
                   'foldmethod' and 'foldexpr' alone. Use it when your
                   config wires tree-sitter features itself.

                                                                *g:masm_stack*
g:masm_stack       Optional table configuring stack analysis; all fields
                   optional, defaults shown: >lua
                     vim.g.masm_stack = {
                       diagnostics = true,     -- publish diagnostics
                       overlay = false,        -- overlay on for new buffers
                       overlay_mode = "auto",  -- "auto" | "all"
                       check_comments = true,  -- verify `# =>` comments
                       bail_hints = false,     -- HINT unanalyzable procs
                       debounce_ms = 300,      -- edit debounce
                     }
<
                   Read on every refresh; changes apply to the next
                   analysis pass.

                                                             *g:masm_no_stack*
g:masm_no_stack    When true, stack analysis is not wired at all for new
                   `masm` buffers: no autocmds, no |:MasmStackToggle|, zero
                   cost. |masm.stackview.attach()| remains callable, so a
                   per-project autocmd can still opt chosen buffers in.

                                                               *g:masm_no_dap*
g:masm_no_dap      When true, nothing is registered with nvim-dap and
                   |:MasmDapState| is not defined.

9. API                                                        *miden-masm-api*

The functions below are the plugin's public Lua surface -- the ones custom
mappings call when |g:masm_no_default_mappings| is set. Everything else
under `lua/masm/` (including `_`-prefixed fields) is internal and may
change.

Multi-return convention: functions documented as returning `item, reason`
return the value on success, or nil plus a human-readable reason string on
failure.

resolve()                                               *masm.goto.resolve()*
    `require("masm.goto").resolve()` resolves the name under the cursor
    exactly as `gd` would, without jumping. Returns the tag item
    `{ name, filename, cmd = <lnum>, user_data = "symbol"|"module" }`, or
    nil and a reason (`item, reason`). Hover (|masm.hover.hover()|) builds
    on it; custom mappings can too.

references({opts})                                   *masm.goto.references()*
    `require("masm.goto").references()` finds all references to the symbol
    (or module) under the cursor and populates the quickfix list,
    definition first (the `grr` mapping). The scan is asynchronous: the
    function returns immediately and the quickfix list opens when the scan
    completes. Pass `{ sync = true }` to block until done; the sync form
    also returns the quickfix-style items
    (`{ filename, lnum, col, text }`), or nil when none were found. Note
    that both forms populate and open the quickfix window as a side
    effect -- the sync form before returning.

rename({new_name})                                       *masm.goto.rename()*
    `require("masm.goto").rename()` renames the symbol under the cursor
    across the project; semantics are those of |:MasmRename|. With
    {new_name} omitted it prompts via |vim.ui.input| (and returns nothing);
    with {new_name} given it applies synchronously and returns a summary
    `{ applied, skipped, files }`, or nil and a reason.

document_symbols()                             *masm.goto.document_symbols()*
    `require("masm.goto").document_symbols()` lists the buffer's top-level
    definitions in the location list and opens it (the `gO` mapping).
    Returns the location-list items, or nothing (after a notification)
    when the buffer has no definitions.

module_symbols({bufpath}, {segs})                *masm.goto.module_symbols()*
    `require("masm.goto").module_symbols()` returns the visible interface
    of the module named by {segs} (a list of path segments, e.g.
    `{ "std", "math", "u64" }`) as resolved from file {bufpath}: the
    module's own definitions plus the names it re-exports, as a sorted
    list of `{ name, kind, path, lnum }`. Returns nil and a reason when
    the module cannot be resolved.

kernel_symbols({bufpath})                        *masm.goto.kernel_symbols()*
    `require("masm.goto").kernel_symbols()` returns the interface of the
    project's kernel library (the `[lib]` with `kind = "kernel"` in its
    manifest -- what `syscall.` targets resolve against), in the same
    `{ name, kind, path, lnum }` list shape as
    |masm.goto.module_symbols()|. Returns nil and a reason when indexing
    fails or the project declares no kernel library.

clear_cache()                                       *masm.goto.clear_cache()*
    `require("masm.goto").clear_cache()` drops the cached project index and
    the resolution caches -- the navigation half of |:MasmRebuildIndex|
    (the command additionally drops the stack analyzer's memos). Needed
    after deletions, moves, or changes made outside Neovim; ordinary saves
    invalidate the affected entries automatically.

hover()                                                  *masm.hover.hover()*
    `require("masm.hover").hover()` shows the hover float for the name or
    opcode under the cursor (the `K` mapping). Calling it again while the
    float is open focuses the float.

analyze_lines({lines}, {path})                  *masm.stack.analyze_lines()*
    `require("masm.stack").analyze_lines()` runs stack analysis on {lines}
    (a list of strings) as the content of the file at {path} -- callee
    contracts resolve relative to that path. Pure with respect to the UI:
    no notifications, no buffer access. Returns
    `{ procs = {...}, diagnostics = {...} }` where each diagnostic is
    `{ lnum, col, severity, code, message }` (1-based `lnum`, severity
    `"error"`/`"warn"`/`"hint"`, codes as listed in |miden-masm-stack|),
    or nil and a reason.

analyze({bufnr})                                       *masm.stack.analyze()*
    `require("masm.stack").analyze()` runs |masm.stack.analyze_lines()| on
    the current content of buffer {bufnr} (nil or 0 means the current
    buffer), with the buffer's file name anchoring resolution. Same return
    convention; an unnamed buffer returns nil and a reason.

toggle({bufnr})                                     *masm.stackview.toggle()*
    `require("masm.stackview").toggle()` toggles the inferred-stack
    ghost-text overlay for {bufnr} (nil or 0 means the current buffer) --
    the function behind |:MasmStackToggle|. A no-op for buffers stack
    analysis is not attached to (non-masm buffers, or when
    |g:masm_no_stack| is set).

attach({bufnr})                                     *masm.stackview.attach()*
    `require("masm.stackview").attach()` wires stack analysis to {bufnr}
    (nil or 0 means the current buffer): re-analysis is debounced on
    |InsertLeave| and |TextChanged|, immediate on |BufWritePost|, torn
    down on |BufUnload|, and a first refresh is scheduled (the file-open
    path is never blocked). Idempotent per buffer. The ftplugin calls this
    for every `masm` buffer unless |g:masm_no_stack| is set -- with that
    set, attach()/detach() are the supported per-buffer opt-in path.

refresh({bufnr})                                   *masm.stackview.refresh()*
    `require("masm.stackview").refresh()` synchronously re-analyzes {bufnr}
    (nil or 0 means the current buffer) and republishes the diagnostics,
    the import canary and the overlay (when enabled). A no-op for buffers
    not attached; buffers over the 2 MiB analysis gate are refused with a
    one-time notification.

detach({bufnr})                                     *masm.stackview.detach()*
    `require("masm.stackview").detach()` detaches stack analysis from
    {bufnr} (nil or 0 means the current buffer): autocmds and the debounce
    timer are torn down, the overlay and the published diagnostics are
    cleared. Idempotent; call |masm.stackview.attach()| to re-enable.

10. NAME RESOLUTION                                    *miden-masm-resolution*

The resolver mirrors the Miden assembler's project model:

- A library is a directory holding `miden-project.toml` whose `[lib]` table
  gives `namespace` (e.g. "miden::standards") and optionally `path` to the
  root module file. Submodule `a::b` lives at `<root>/a/b.masm` or
  `<root>/a/b/mod.masm`. Account components are single-file libraries named
  after their directory. The `kind = "kernel"` library is what `syscall.`
  targets resolve against.
- `use miden::foo::bar` imports module `bar`; `use .. as x` renames it;
  `use {sym, orig as alias} from <module>` imports symbols directly and may
  span multiple lines.
- `pub use` re-export chains are followed, tracking renames at every hop,
  until the underlying `proc`/`const`/`type` definition is found.

The index roots at the git root (or the outermost directory containing a
`miden-project.toml`) and is cached for the session. Saving a `.masm` file
the index has not seen, or any `miden-project.toml`, refreshes it
automatically; resolution results are freshness-keyed on every file a
lookup consulted, so editing ANY hop of a re-export chain re-resolves.
Deletions, moves and out-of-editor changes need |:MasmRebuildIndex|.

11. LIMITATIONS                                       *miden-masm-limitations*

- The pinned tree-sitter grammar (upstream HEAD -- there is nothing newer to
  pin) predates the current dialect: `use {..} from ..`, `pub mod` and
  `use .. as ..` parse as ERROR nodes, which mainly affects import headers
  (and `mod.masm` files). Navigation is text-based for exactly this reason
  and is unaffected; unrecognized future import forms surface as
  `unrecognized-import` diagnostics rather than failing silently.
- Resolution is by convention, not by running the assembler; unresolvable
  names report a reason instead of guessing.
- Re-export chains are followed up to 5 hops; deeper chains report "not
  found". Cycles are detected and fail cleanly.
- A multi-line `use { .. } from` block longer than 40 lines is not
  recognized when the cursor is inside its braces (real-world blocks run to
  ~20 lines).
- The project index is one bounded directory walk. It is built by the
  first stack-analysis pass, scheduled a moment after the first `.masm`
  buffer opens (stack analysis is on by default); with |g:masm_no_stack|
  set it is built synchronously on the first jump instead. Reference scans
  and renames read files as they go, so a very large `extra_roots` still
  costs time -- but references do not block the UI while scanning.
- Rename rewrites the definition-site spelling everywhere it appears; it
  does not offer to rename aliases (`use { x as y }` keeps `y`), and it
  cannot know about generated code or docs outside `.masm` files.
- Hover shows what the definition site documents. The instruction reference
  is a generated snapshot (see `lua/masm/instructions.lua` for provenance).
- Stack analysis is a static approximation: absence of diagnostics is not a
  correctness proof. Procedures without an `#! Invocation:` tag are skipped;
  `dynexec`/`dyncall` targets and undocumented `exec` callees make the state
  unknown until the next handwritten `# => [...]` comment; `exec`s that
  reach the 16-element floor have internals-dependent depth and are likewise
  resynchronized from comments; elements genuinely consumed from the caller
  before a later poison go unreported as caller-underflow unless a resync
  clears the unknown state before the procedure ends (the analyzer never
  warns on a state it declared unknowable); comments in `exec`-invoked
  procedures are never flagged (they legitimately mix views); a reordered
  comment is only caught when both sides are fully named with matching
  multisets -- renamed elements in the wrong order remain invisible;
  unknown instructions skip the procedure with a stated reason.
- Debugging needs nvim-dap plus miden-debug / miden-client builds that
  support `--start-debug-adapter`.
